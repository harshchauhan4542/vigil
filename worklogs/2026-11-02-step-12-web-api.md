## What was done

- `apps/web`: Next.js 16.3.6 + React 19.2.8 app shell, `output: 'standalone'`, built with webpack (`--webpack`) because Turbopack doesn't map the packages' `./x.js` specifiers to `.ts` sources; server externals forced for PGlite/pg/ioredis/pino/Render SDK.
- Routes: `GET /api/health`, `GET /api/exceptions` (queue + latest proposal), `GET /api/proposals/[id]` (no token hash exposed), `POST /api/proposals/[id]/approve` (serialised per proposal, rate-limited, signed session cookie, T3 `typed_amount`), `POST …/reject`, `GET /api/events` (SSE over the append-only audit log, works across processes), `POST /api/agent/stream` (SSE of the Claude loop; daily token budget; new DRAFTs evaluated by policy), `POST /api/webhooks/paypal` (raw bytes, always Live), `POST /api/demo/reset`, `POST /api/demo/mode` (per-judge Live ⇄ Replay cookie), `GET /api/audit` (rows + chain verification).
- `lib/server.ts`: one server per mode (Live/Replay) per process; DB + PayPal + Claude through the replay transport. `lib/inline-runner.ts`: the only web file allowed to load `@vigil/workflows` (inline/replay runner); on Render in Live mode the web app uses `RenderTaskRunner` and never loads execution code. New lint boundary + tests.
- `lib/guards.ts`: HMAC-signed session cookie, per-IP fixed-window rate limiter, per-key serialisation.
- `@vigil/db/views.ts`: `listQueue`, `auditSince`, `latestAuditSeq`, `listAudit`, `agentTokensSince`. `createDb({ migrationsDir })` for bundlers.
- `@vigil/workflows/testing`: the fake PayPal, shared with web tests. Vitest timeouts raised for PGlite-backed packages (parallel-load flakiness).
- `scripts/api-walkthrough.sh`: curl walk-through of one exception (health → queue → proposal → approve → result → audit chain). `pnpm dev`.
