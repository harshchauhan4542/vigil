## What was done

- `render.yaml` Blueprint: Postgres 16 (`vigil-db`), Key Value (`vigil-kv`), `vigil-web` (`next start`), `vigil-detect` cron (every 15 min: detect + settle_check), `vigil-nightly-reseed` cron (02:30 UTC). One env group **`vigil-shared`** so web and workers share the generated `APPROVAL_HMAC_SECRET` / `SESSION_SECRET`; all keys are `sync: false` (dashboard only).
- `apps/workflows/build.mjs` (esbuild): bundles `dist/worker.js`, `dist/cron.js`, `dist/cli.js`; workspace TypeScript + pure-JS deps inside, wasm/native/worker packages external (direct deps). Verified: the worker loads and registers all tasks; the CLI applies migrations and runs detect (fails loudly on the missing Replay fixture, as designed).
- Bundled entry points pass `migrationsDir` explicitly.
- **Auto-fallback to Replay** (`apps/web/lib/server.ts`): if Live can't start (config/keys), Replay is served, the reason is shown in the banner and `/api/health.fallback`, Live is retried every 5 minutes, and the webhook route returns 503 so PayPal retries. Env is validated per mode (`envFor(mode)`).
- `docs/deploy.md`: click-by-click (Blueprint, Workflow service by hand named `vigil-workflows`, Render API key, PayPal webhook + `PAYPAL_WEBHOOK_ID`, seed/record/verify, local `cloudflared` option, audit-log note).
- Web: dropped `output: 'standalone'` (Render runs `next start` in the built checkout).
